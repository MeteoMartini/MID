Die Produkt-Funktion `rucWindowFresh` erlaubt explizit +5 min. Die alte Assertion `shift=+1` musste zu dieser Uhrzeit fälschlich scheitern. Neuer Test `shift=+2` bleibt bei **jedem** Zeitpunkt außerhalb dieser Toleranz und erhält Negativtest für `shift=-5`. Zusätzlich separate fixe Epoch-Grenzprüfungen: zulässig exakt +5min und -4h, unzulässig jeweils eine Millisekunde jenseits; weder Frische-, Physik-, EPS-, Phasen-, Extremwert- noch NoData-Produktlogik verändert.
