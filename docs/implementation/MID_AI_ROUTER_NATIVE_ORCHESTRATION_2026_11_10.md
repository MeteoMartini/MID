# MID AI Router 1.2 – native ChatGPT, Work/Codex, Copilot and true Free-model execution architecture

Status: QA Draft #728, 2026-11-10. This is a design / offline regression artifact, NOT a deployment, verified account connection, actual provider request or permission to merge or release. All existing MID AGENTS/source/cost/CI/contracts remain mandatory. Do not put secrets or user data in GitHub.

## The two independent routing layers

1. **Surface/intent selector (implemented as pure QA planner):** `scripts/mid-ai-router-capability.mjs` selects the least costly sufficient already connected capability for an explicit task, using current host availability and permissions: GitHub direct source/readback, native web/Firecrawl/Context7 research, PostHog only if consent verified, Product Design for UX, Work for multi-step artifacts/browser work, Codex for eligible coding, GitHub Copilot issue/Draft for bounded untrusted coding if included quota/overage state is independently verified, or external model review only after a trusted MCP execution backend. When Work/Codex is not the actual host, the planner returns `MODE_SWITCH_REQUIRED` – it **cannot programmatically switch the ChatGPT UI**. ChatGPT may recommend the right host; a supported Codex SDK/app-server runtime requires a separate actual connection.
2. **External model selector:** `rankMidAiFreeCandidates` ranks only *fresh independent task-specific measured* quality results for exact free models with verified account, rate limits, privacy and zero-cash proof flags. Static ranking is not equivalent to measured quality. No benchmark scores are invented. Two-model blends require distinct foundation publishers/families and two signed one-shot reservations. A plan is always `dispatchAuthorized:false` until an independently attested, authenticated executor has separately verified the conditions. A fallback to a paid model, auto model substitutions or reduced privacy are not allowed. Existing `mid-ai-router.mjs`, Ed25519 signing and QA-only local ledger retain their own stricter guards.

**Connected plugins are NOT model API endpoints.** Native ChatGPT executes already connected tools itself; public OpenRouter/Groq/Gemini APIs are a separate identity, quota, cost, source and authorization boundary. ChatGPT Plus or GitHub Copilot Pro does not itself grant arbitrary OpenAI API/Groq/OpenRouter/Gemini quota. Copilot cloud agent can be started by the existing permitted Issue assignment; it is not an inference proxy. Copilot's separate Agent Tasks API needs user-to-server token and independent entitlement, not the current GitHub App installation token. Output is untrusted Draft and cannot release MID.

## Concrete, genuinely free and secure MCP runtime candidate

A dedicated **Cloudflare Workers Free account/project** with SQLite Durable Objects is technically plausible: official [Durable Objects Free price / fail-at-quota](https://developers.cloudflare.com/durable-objects/platform/pricing/) states SQLite Durable Objects are free-plan eligible; limits trigger failure rather than extra charges. Do not assume MID's current Cloudflare account is Free or that a paid-plan account cannot incur overage. A new no-payment Free account would require the user's explicit account connection/authorization. No Cloudflare API/permissions, worker namespace, deployed MCP endpoint or provider API keys have been verified here; hence **no deployment performed**.

Planned endpoints: `GET /mcp` authenticated health/tool discovery; `POST /mcp` authenticated Streamable HTTP MCP, `list_models_status` read-only, `plan_request` pure, `execute_public_review` write, optionally `compare_two_reviews` bounded two request authorizations. Each uses per-user OAuth 2.1 PKCE/resource audience validation; no anonymous inference, no broad account credentials, no generic remote code execution, no cookies/keys in user-facing results. Server secrets provisioned only after a verified account; least-privilege provider keys. Durable Object single-writer SQLite conditional insert of request-id + signed grant fingerprint *before network*, global per-account free quota reservation, no retry after timeout/ambiguous response, no fallback to paid model. Response includes exact served model/version, prompts redacted, source requirements, usage **unknown instead of 0**, latency/cost unknown when unverified, and originating stable SHA. All failed authentications, duplicates, missing quota and invalid source versions fail closed.

Official integration docs: [OpenAI plugin MCP server](https://developers.openai.com/plugins/build/mcp-server), [OAuth](https://developers.openai.com/plugins/build/auth), [Cloudflare OAuth MCP](https://developers.cloudflare.com/agents/model-context-protocol/protocol/authorization/), [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [Work/Codex](https://help.openai.com/de-de/articles/20001275-chatgpt-work-and-codex).

## 10.11.2026 — signed quota attestation before Durable Object reservation (QA only)

The new `scripts/mid-ai-router-signed-quota.mjs` verifies an independent **Ed25519-signed, field-exact, five-minute quota grant** using the WebCrypto algorithm supported by Cloudflare Workers and Node 22. The key ID and raw public key are pinned through the trusted operator configuration, never from the caller; private signing key stays entirely outside the MID repository, Cloudflare executor, ChatGPT and source PRs. Signer assertions bind one user-authorized request ID, task digest, exact Stable SHA, fixed Free provider/model, hashed quota subject, daily quota, privacy approval and **0 additional cash**. A separately authenticated fixed-origin GitHub source readback must still confirm `main=mid-stable` within 30 seconds. The verified immutable proof can be passed to the existing `createMidAiGlobalAdmission`, whose SQLite synchronous transaction consumes request-ID and daily quota exactly once before any possible upstream call. The signed grant **does not itself prove a real Free account or bill-safe quota**: a future independent issuer must check real provider credentials, billing controls, quota and GDPR/privacy state before signing; a protected OAuth MCP server and provider executor are also missing.

This is `QA_ONLY`. Tests use ephemeral local test signer keys, mock GitHub readback, real local SQLite transaction and negative tamper/expiry/billing/data-scope cases. Production keys, actual provider calls and Cloudflare deployment: **NONE**. Official basis: [Cloudflare WebCrypto Ed25519](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/), [Durable Object SQLite transactionSync](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [MCP authorization](https://developers.cloudflare.com/agents/model-context-protocol/protocol/authorization/). Client limitation: [OpenAI custom MCP entitlement](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt) – full MCP with actions/write is not an established capability for a Plus account; a separate user-entitlement check is a prerequisite before claiming direct ChatGPT execution. **No attempt to disguise inference as a read-only MCP tool is permitted.**


## Bound principal before any future production use

The signed grant and atomic claim now bind a 64-character cryptographic **OAuth principal digest** (`principalSha256`) in addition to request ID and provider-account quota subject. The digest is derived by the protected OAuth resource server from a verified audience and subject, NOT accepted as a caller-chosen identity. A stolen valid signed request presented under another authenticated principal must fail before quota admission or network. The quota subject remains the independent hashed provider-account bucket and must not be chosen from a request ID (avoids quota sharding). This is an **offline-integration contract**, not evidence that the OAuth server exists or is connected in ChatGPT Plus.
