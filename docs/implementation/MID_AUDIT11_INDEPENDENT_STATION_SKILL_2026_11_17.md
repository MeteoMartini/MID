## Meteorological data contracts

- DWD CDC: `historical` denotes operationally QC-completed station records; `recent` is provisional. Preserve station IDs, original UTC validity/accumulation periods, measured quantity units and original station metadata (relocations, gauge changes, reference-time changes, algorithm changes); do not treat them as one unbroken instrument/site history. For a future DWD adapter use primary provider records with rights, geographic distance/height and parameter-specific availability; never make up station values.
- `TwinStationPair` requires an *already confirmed* official measured station, QC-checked history, metadata validation and same archived issue/valid interval for MID candidate and baseline. This plain-object **admission flag alone does not prove** DWD provider authenticity. The source adapter and independent fetch provenance must be audited before production. Model, reanalysis, provisional and private sensor data are intentionally excluded from this *public official-station* score; private sensors can receive separate, explicitly labeled personal diagnostics.
- Forecast issuance <= original archive timestamp < valid start; measured value cannot be available before valid end; actual observation available by specified as-of cutoff. No hindsight, null→0, negative rainfall, invalid probability, mismatched accumulation or duplicated station/date/lead-window counted. For rain amount or rain Brier require an independently verified **complete original accumulation window**, not the previous 18h heuristic; use #911 `verifyTwinDailyAccumulation` once source interval data genuinely exists. The scored event is observed rain **strictly > thresholdMm**, candidate and baseline as fractions 0..1, both same threshold and validity.
- Temperature/precipitation use paired absolute error (°C or mm). Probabilities use proper Brier squared error (dimensionless). Never sum those heterogeneous quantities into one quality score. Group by lead bands 0–6, 6–24, 24–72 and 72–168 hours and explicit rain threshold. Local target dates are checked against the actual station IANA time zone, including end-at-midnight accumulation semantics and DST, and cannot be relabelled to inflate independent days. Multiple locations or captures on one local target date are averaged **within** the day; day-level errors are then equally weighted. Diagnostic 30/90-day windows are passed as *absolute boundaries* from the caller (IANA/local-day conversion required); no hidden 24h-fixed calendar/day calculation.
- For >=30 consecutive distinct local calendar dates a **deterministic 400-draw moving 7-calendar-day block bootstrap** yields an *exploratory* paired improvement interval, not scientific proof or a WMO minimum. A missing date or <30 dates yields no CI, not an artificially precise interval. All reports remain `exploratory-only` / `insufficient-days`; no positive CI ever automatically activates a forecast. Appropriate block length, effective sample size, weather/season strata and observational representativeness still require independent methodological assessment before public scientific claims.
- No actual DWD data are downloaded by this module. No empirical temperature MAE, Brier, CSI/POD/FAR, CRPS or 72-hour real-world trial has been verified here. The extra metrics CSI/POD/FAR/CRPS require a separate verified event forecast/ensemble source and sufficient matched observations; do NOT extrapolate them from the narrow module.
