## P1/P5 – evidence chain

- Existing `mid-ruc-availability-observer.yml` produces best-effort 15-minute directory listings and public Pages/Worker observations. A green job may have **skipped** all observation steps (e.g. #41292543651). Historical original ZIP #41264383379 lacked the new observer status and must NOT count as a positive sample.
- New `tools/ruc/ruc_github_observer_collect.py` reads the exact GitHub Actions workflow-run inventory (8-day lookback for the last 168 model hours), actual run IDs/attempts, GitHub-created timestamps, source SHA, state and conclusion. It downloads only the exact named original ZIP for a *successful, completed* run. A missing, failed, expired or incomplete run is a gap, not a zero or a positive. Pagination, duplicate runs, excessive artifacts, wrong source/event and data transfer errors fail closed. The original GitHub artifact digest is SHA256-verified when exposed by GitHub; otherwise the archive SHA256 is recorded as independently computed, explicitly **not** as GitHub-signed.
- Strict ZIP member/path/size/duplicate-key/status/lineage/content validation uses the verified original draft #576 bundler. Network redirects can never carry the API bearer token to artifact-storage endpoints. Archive output is staged atomically, with unmodified original ZIPs available locally during processing; the workflow uploads only bounded provenance, original JSONL/readbacks and censored statistics, **not** all downloaded ZIPs.
- Reuse the existing `ruc_p1p5_censor_audit.py` with an exact UTC cutoff. Its percentiles mean **first-observed directory/public upper bounds**, never the actual original DWD publication instant, verified GRIB/EPS20 values or authenticated browser/widget refresh. Unknown/left/right/interval-censored run slots and gaps remain distinct. Missing is never 0 and extreme events are not smoothed.
- New `mid-ruc-observer-evidence-archive.yml` only reads stable when main and stable have identical full SHAs, uses `contents: read` + `actions: read`, pinned actions, read-only GitHub API and 14-day archived reports. After release and separate workflow review it has a daily best-effort schedule plus manual dispatch. A successful archive job **alone** never authorizes Fast-Lane publication or an SLO.
- QA: 17 ported original ZIP adversarial tests plus **19 additional offline collector tests** passed locally. Both canonical/active workflow mirrors must be byte-identical. Real GitHub CI and a first live archive run on the actual PR/promotion SHA are separately required; the local test is not a real GitHub API end-to-end result.
