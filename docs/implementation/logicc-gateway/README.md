## Review disposition — immutable 0.1.1 scope

- The routing restriction applies to the Cloudflare **plugin**, never to the narrowly authorized, separately authenticated human owner path defined in the binding governance revision. No new account or token permissions are granted.
- Existing GitHub App/installation permissions include issues:write and pull_requests:write by design of the already configured handoff App. This does not make the App read-only. The gateway API exposes only two qualification tools; the POST requests a metadata:read-only test token, checks the returned exact permissions, and uses it only for repository selection readback. The server-side private key remains privileged; compromise could expose the existing App authority. Do not broaden or change App permissions for this release. Owner-side secret isolation, selected-repository scope, and independent live qualification remain mandatory before any deployment acceptance.
- MCP readOnlyHint describes absence of repository mutations, not absence of all upstream side effects: mid_app_qualify issues an ephemeral metadata-only installation token through POST. This is not an idempotent token issuance guarantee. Token material is neither returned nor logged. The unchanged 0.1.1 candidate does not immediately revoke that token; this is a residual hardening item. Verify the provider expiry is bounded to at most one hour in live acceptance. If expiry or scope is unverified, stop. Require explicit token revocation/cleanup, including failure paths, and accurate annotations in a separately hash-qualified successor before any future write-enabled integration; no such integration is authorized here. No changes to the frozen worker or original diagnostics bytes in this governance release.
- The existing required runner regression now invokes the original Node syntax check and diagnostics through bounded local child processes; no upstream requests, keys or deployment permissions needed. These offline tests are not authenticated Cloudflare/Logicc acceptance.
