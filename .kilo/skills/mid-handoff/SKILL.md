# MID Kilo work and handoff

1. Before work read `AGENTS.md`, `MID_BASELINE.json`, `MID_SOURCE_OF_TRUTH.md`, `package.json`, and relevant normative contracts; verify exact live SHAs of `main` and `mid-stable`; identify active PRs and parallel work. If drift or overlap, stop changes.
2. Run in a dedicated **local** worktree branch off the verified latest `mid-stable` commit. Never commit on `main` or `mid-stable`. Kilo cannot create/update protected `chatgpt/*`/`codex/*` refs. Do not attempt to push those refs and never use force, bypasses, SSH credential fallbacks or broaden GitHub permissions.
3. Work only within the scope of the user's task, retain all existing functions, tests and WMO/DWD contracts. Apply least-privilege; never access or copy secrets.
4. Run focused relevant tests and document exact pass/fail evidence. Do not claim browser tests are real iOS/VoiceOver acceptance. Leave intentional version updates and full release to trusted MID integration.
5. When a user-assigned implementation reaches a safe review checkpoint, save the scoped change in the isolated local branch; ensure `git status --porcelain` is empty. Execute the available focused tests and document exact results. Tests not executable in Kilo (including unavailable Node 22, `npm ci`, aggregates, browser or real iOS) must be labeled `NOT VERIFIED` for independent Draft QA; never convert them to passes. Preserve the local commit if any handoff fails.
6. **Default after user-initiated MID coding work:** the user's concrete Kilo implementation/fix instruction is standing permission for **one** scope-restricted, ref-free candidate handoff, without separately asking the user to relay code, a patch or a technical command. Verify the trusted `scripts/mid-kilo-handoff.mjs` from current Stable; if missing, STOP and do not recreate it from memory. Run `node scripts/mid-kilo-handoff.mjs --title "<short descriptive topic>" --dry-run`, validate Stable SHA, the changed-file manifest, clean local tree and allowed scope; if all preconditions pass and no explicit user opt-out or conflicting contract exists, run the same command once without `--dry-run`. It creates only immutable Git objects and one intake issue, **no** refs, branches, PRs or releases. Never submit a read-only/audit-only task, unapproved new feature, suspicious file/symlink, unrelated diff or task with missing authorization. The separate trusted ChatGPT intake can create at most a Draft PR.
7. If the script fails because GitHub does not permit writing Git objects/issues (or for any other reason), leave local commits untouched, report the precise blocker once and **stop**. Do not fall back to creating unauthorized branches or using new credentials. No local reset, no rebase, no deletion of an ephemeral worktree until the handoff issue and remote object have been verified.
8. A successful issue is a **candidate**, not acceptance. Await independent integration, full gates and release. Always report the issue URL, remote candidate SHA, local HEAD, exact stable SHA, tests, and remaining blockers.

Kilo's Cloud Agent may run tools automatically. This skill is policy guidance and does not replace server-side branch protection or the independently authorized GitHub release actor. Never auto-merge or self-release.

A token/readback/identity failure requires inspecting already-created objects/issues, **never blind resubmission**.

## MID quality and continuity requirements

- The task must name its exact permitted paths, non-goals and acceptance criteria. Preserve prior accepted work; do not rebuild #655 cache components or #657 UI-P0. A failed installer is not a published release. Read the current integration state before touching overlapping files.
- Find canonical sources before editing generated files. Presentation CSS is assembled by `scripts/build-maintenance-aggregates.mjs`; #657's UI source is `src/midC48TabletTimeline.css`. Do not overwrite only `src/midPresentation.css`. Resolve aggregate ownership from the checked-out generator and run the required mirror validation within the authorized scope. Leave Worker, CI/governance, iOS, versioning and release configuration to trusted integration.
- Preserve selected design decisions: Skybar above temperature; existing map/model functions, favorites and persistent settings; shared weather icons/colors/value formatting. Missing is never zero. Keep model initialization, valid time, accumulation, units, provenance and uncertainty consistent; official warnings remain distinct.
- Validate on the CI Node 22 runtime. Provide the original regression before/after a behavioral fix and deterministic negative cases. CacheStorage fixtures store immutable bytes/headers and return a fresh Response per match. Never raise timeouts, relax assertions or budgets, or omit browser cases to obtain green CI.
- Check small/large phones, tablet portrait/landscape and desktop in Light/Dark, including long place names, wrapping, first-tap behavior, focus, overlays/overflow, Safe Areas, existing 52px navigation and minimum 44px touch targets. Include actual screenshots and interaction results. Browser/fixture runs do not establish real iOS or VoiceOver acceptance.
- Return task ID, exact Stable/base/parent/local HEAD/tree/remote candidate SHAs, path manifest with Git blob hashes, minimal diff, exact commands/exit codes/CI links, viewport evidence and remaining limitations. `Candidate-SHA` is the uploaded source; `Local-HEAD` is separate provenance, never silently interchangeable. Submission, independent acceptance, CI and publication are separate states.
- The existing external MID Kilo-Handoff-Integration watcher is the intended intake. Do not build another workflow or grant Kilo ref/PR/release rights. #659 proves only the completed Blob/Issue permission test; do not repeat it or submit that QA_ONLY issue as a handoff. A complete live Tree/Commit/Issue-to-authorized-Draft-PR probe remains required before claiming end-to-end operation. Read `docs/implementation/MID_KILO_HANDOFF_BRIEFING_2026_11_05.md` and reverify all historical SHAs there.
